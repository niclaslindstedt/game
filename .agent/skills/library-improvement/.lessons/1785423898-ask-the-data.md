---
title: A generated page must never ASSERT a content rule — ask the data
date: 2026-07-30
---

The powerup catalog documents a flat rule: every venue's pool KEEPS what came
before. So the generator's prose said so — "every venue from here on keeps it,
so the same power thins out the further down the campaign you take it" — which
is exactly the kind of sentence a generator should never contain.

`content/levels/the_bunker.yaml` does not keep BOOT HILL's two powers. The page
therefore printed a rule and, three inches below it, a table denying it. Worse,
the section's index filed the screen-nuke under "reachable only through a mod",
because the bomb is in no venue's pool at all — it has two channels of its own
in `loot.ts`. That is a page confidently lying about the most familiar power in
the game.

The rule that falls out: **anything a page states about how the content is
ARRANGED has to be computed from the content, not copied from the doc that
describes it.** In practice that is one boolean on the model per claim
(`keptThroughout`), and the prose picks its sentence off it. It costs a line and
it makes the page incapable of contradicting its own table.

The corollary is that this is how the library EARNS its keep. Nobody reads six
level YAMLs side by side; a generated page that puts the pools in one column
does, and the two content bugs above surfaced the first time the section was
rendered. Expect a new section to find something — and when it does, fix the
PAGE to tell the truth first, and raise the content question separately rather
than quietly rebalancing a map to make a sentence true.
