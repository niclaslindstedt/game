---
type: Added
title: A mod author gets the game's own measuring instruments — one `--mod` flag
---

Every analyzer, renderer and simulator this game's own content was built with
now takes **`--mod <dir>`** and reports on the MODDED game: the map renderers
(`level-render`, `map-layout`, `map-preview`, carved blueprints included), the
campaign simulator with its PASS/WARN/FAIL verdict, the drop-rate, progression
and mob-hp probes, the whole weapon and relic battery (`weapon-budget`,
`weapon-stats`, `item-forge`, `weapon-ilvl`, `unique-check`, `weapon-sheet`,
`weapon-scatter`), and the sprite sheets — plus `playtest.mjs`, which now drives
a mod in the REAL renderer through the app's own mod loader. The flag is
repeatable and ordered, so it can stack mods exactly as a player's load order
does.

The mod compiler answers whether a mod is VALID; nothing answered whether it is
any good — so a mod author authored blind against a game whose own venues,
monsters and weapons are judged by rendering them, simulating them and pricing
them. `mod/AGENTS.md` now has the whole loop in the order a mod gets built
(LOOK at the map → PLAY it → MEASURE the balance → PRICE the loot → LOOK at the
art), which of this repo's agent SKILLS apply to mod work and which are the
game's alone, and an honest list of what does not take the flag.

Nothing about the format changed: `--mod` runs the same compiler the shipped
game runs and registers the result through the same seam, so a tool measures
what players will actually get.

Three bugs the new instruments immediately found, all fixed: a level with no
`landmarks:` (a mod is allowed none) crashed the moment its map scattered a
prop; `?level=` ignored a mod's own venue and started the campaign's first map
instead; and the worked example mod shipped invisible walls, an under-budget
weapon, an out-of-band loot pool, and a relic wired to nothing that could never
drop.
